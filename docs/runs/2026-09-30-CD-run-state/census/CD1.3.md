Outcome-flakiness is low (safety assertions), POWER-flakiness is high (see wrong-reason list).
 - `docker ps ... grep -q 'checker'` (L279, L300) matches unrelated containers and stale `*-checker` containers left by a killed earlier run: the loop breaks at once and the rotation/kill fires before this run's container exists. rot(): a rotation before the harness's pre-run read would turn rotate-old into a secret-free run (check then fails).
 - rot() launches the harness BEFORE `mkdir -p "$d/htmp"` (L277-278; run() and the TERM/KILL blocks create it first): if `mktemp -d "$TMPDIR/..."` ran first the run skips container-error. Low probability (docker info + compose version precede mktemp).
 - `H no containers/networks left` compare global `docker ps -aq | wc -l` / network counts against a baseline taken at L36: any other session's container churn on this docker host flips them (attempt-2 checker saw exactly this).
 - Concurrency: fixed image names + S-step retag (L84) make two oracle runs on one docker host interfere; the L305-311 sweep is scoped by the compose-file label to $TREE/swarm/codex/ (good) but still hits a concurrent run in the same TREE.
 - Wall clock: ~130 harness runs each with image rebuild + proxy + probes; TERM loop alone ~1 min of sleeps.
Non-issues checked: `( cd "$TREE" && env ... bash "$SCRIPT" ) &` — in bash 5.2 the chain is exec-optimised, so `$!` IS the harness pid (scratch probe: pid comm was the final command), hence `kill -TERM $pid` / `pkill -P $pid` hit the right process. accept.sh and stub-codex pass `bash -n`. The oracle stub's flat record count (~25 + last.json) stays under the 64 cap in every non-`many` scenario.
