(d) The rules hold in the gate AND the dashboard, at tiers 1–3, and the gate's `check` exits 0 exactly when the dashboard's `derived.state` is `accepted`:
  1. `crossvendor` is valid only with `CHECKER: checker-codex`, and `checker-codex` only with `crossvendor`; any other pairing is an invalid verdict file.
  2. `codex` may appear in the ledger checks column but never counts as a named checker; a column naming only `codex` is refused like a blank one.
  3. When `codex` is named, the CURRENT attempt needs a valid Codex verdict OR a valid skip record, else refused with `missing checker-codex evidence (attempt N)`; both at once → refused; older attempts do not count. A valid skip record is a regular file with no NUL byte whose FIRST `REASON:`, `DETAIL:`, `TASK:`, `ATTEMPT:` lines give a listed reason, a non-empty DETAIL, and TASK/ATTEMPT equal to the filename's. Header values: only LEADING ASCII whitespace is stripped, never trailing, never non-ASCII — and the gate's answer must be the same under `LC_ALL=C`, `C.UTF-8` and `en_US.UTF-8`.
  4. A Codex PASS never counts: not as a named checker, not as a lane (the tier-2 `second` span, the tier-3 two-lane rule). It still needs `MANIFEST_SHA256`.
  5. A Codex FAIL is a FAIL: tier 1 when named (`checker-codex returned FAIL`); tiers 2/3 always (judge-panel dispute path); it counts for two-consecutive-fails escalation and in `stats` at every tier.
  6. Not named: tier 1 ignores Codex files for acceptance; tiers 2/3 load Codex verdicts (FAIL counts, PASS never); skip records are ignored.
  7. `gate.sh stats`: each first-attempt line ends ` codex=<PASS|FAIL|skip:<reason>|none> second=<PASS|FAIL|none>` for the current attempt, and a final line `codex: ran n/m, FAIL k, same-verdict-as-second j, codex-only FAIL c` over every (row, attempt 0..N) pair holding a valid Codex verdict or skip record, excluding no-change rows.
  8. A non-regular or unreadable verdict entry (dangling symlink, symlink loop, directory, FIFO, mode-000 file) is an invalid verdict: at tier 1 with codex named it refuses the row with `invalid verdict checker-codex` even beside a valid skip record; the dashboard's `parse()` never opens such an entry and never throws or hangs on one.
  9. `gate.sh done` refuses exactly what `check` refuses.
