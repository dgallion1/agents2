## Claim under test
Plans carry `use_current_month` (default true for new plans and for saved plans that predate the field; explicit false keeps a fixed date). On load AND on save, `StartDate` resolves to the current calendar month and every derived age (`CurrentAge`, `SpouseAge`, `Persons` ages via `PersonAge`, and every healthcare person's `CurrentAge`/`BirthMonth`) follows from birth months. Legacy `current_age`-only plans derive birth months against the ORIGINAL saved date before it advances. Healthcare persons that the live plan never linked by `person_id` (persons named "You"/"Spouse", healthcare "Darrell Gallion"/"Christine") are linked positionally when counts match and every pair's saved age is consistent with the original start date; otherwise none are linked and their ages are untouched. Linked entries mirror `BirthMonth`; user-visible healthcare names survive. The rate-assumptions form has a "Use current month" checkbox that persists the flag and locks the date input.
